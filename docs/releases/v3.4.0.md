# v3.4.0

The GitHub App (beta) is now **installable on Kubernetes with Helm**, from a signed container
image and chart published with every release. Nothing changes for the action: `@v3` callers get
it automatically, `@v3.2.0` pins move to `@v3.4.0`.

## Kubernetes

```sh
helm install prow oci://ghcr.io/cncf/prow-github-actions/charts/prow-github-app --version 3.4.0 \
  --set github.existingSecret=prow-github
```

One replica with nothing else, or several replicas sharing a Redis (`redis.url`); the chart refuses
`replicaCount > 1` without one. Deployment with liveness and readiness probes, Service, optional
Ingress, a CronJob for the scheduled jobs, a PodDisruptionBudget for several replicas. Image
`ghcr.io/cncf/prow-github-actions:3.4.0` (linux/amd64, linux/arm64) and the chart are both
cosign-signed and carry SLSA provenance (`gh attestation verify oci://…`). Full guide:
[Running as a GitHub App → Kubernetes](https://github.com/cncf/prow-github-actions/blob/v3.4.0/docs/github-app.md#kubernetes).

## App server fixes

- A pull request's events now run **one at a time, in order**, as the action's `concurrency:`
  group arranges; before, two events arriving together could race the merge gate.
- `GET /readyz`; graceful `SIGTERM` (in-flight events finish, `PROW_SHUTDOWN_GRACE_MS`).
- `REDIS_URL` shares delivery dedupe and the per-pull-request lock across replicas.
- `docker build` works again (broken since v3.2.0's Worker build step).

## Upgrading

Nothing to do for the action. App users on the `docker run` path: the image is now published, so
`ghcr.io/cncf/prow-github-actions:3.4.0` replaces a local build.

## Verification

The SBOM, its cosign signature and the SLSA provenance are attached to this release; the commands
are under *SBOM and provenance* below.
